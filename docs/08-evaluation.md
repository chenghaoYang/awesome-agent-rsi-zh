# 08 · 评测与度量：如何测 RSI / 自我改进

## 场景定义

不是「再做一个会刷榜的 agent」，而是：**如何测量自我改进能力、自动化 AI R&D 能力、以及元生产力（metaproductivity）**。

## 为什么适合 / 不适合 RSI

| 因素 | 评估 |
|------|------|
| 关键 | 没有度量就无法区分任务过拟合与真正的自我改进 |
| 现状 | 有 AI R&D 任务基准；**几乎没有**标准基准直接测「改进改进机制」 |
| 陷阱 | 用 SWE 分数上升宣称 RSI；忽略预算、基座、子集 |

## 场景小结

- **任务基准 ≠ RSI 基准**。  
- METR **时间视野加倍（约 7 个月）** 是目前与「自动化软件劳动」最接近的公开能力趋势度量，但仍不是「改进改进机制」基准。  
- RE-Bench 揭示时间尺度效应：短时自动化 ≠ 长时替代人类研究员。  
- HGM 的 metaproductivity / CMP 是目前公开文献里最接近「测改进能力」的操作化尝试之一。  
- 社区仍缺：固定预算下的多代 compounding 曲线协议、跨种子统计、对 selector 被改写的单元测试。

## 开放问题

1. 标准化「Generation-k 曲线」报告格式（成本、种子、基座、是否允许改评测）。  
2. 如何对抗评测污染与奖励黑客的元基准。  
3. 将 PF/RSP/FSF 的能力阈值与公开基准对齐。
